# Benchmark scoreboard

[Plain-language version](../docs_simple/scoreboard.md)

How KumoSQL scores on public query-equivalence and SQL evals. No language model runs at evaluation time. "0 wrong" means no proof was contradicted by a random-database check. Unknown is always preferred to wrong.

**The equivalence prover's own evals (SQLSolver, QED, R-Bot, Cosette and SPES, VeriEQL, Singh and Bedathur, SQL-IQ, bounded verification, conditional equivalence, join rewrites, output properties, constraint rewrites and the typed soundness fuzzer) are scored in [Kumo_SQL_Prover](https://github.com/wojoe-444/Kumo_SQL_Prover#benchmark-scoreboard), where the prover now lives; its own run owns those numbers.** The tables below hold the evals that need KumoSQL itself (rewrites, pipelines, lineage, Dataform, GoogleSQL support and the like). KumoSQL keeps a small canary of the prover cases (`tests/test_prover_canary.py`), so its own gate still notices a broken dependency.

Evidence levels are kept apart: unbounded proof, bounded verification and agreement on executed datasets. Each row comes from one file in `benchmarks/results/` (format in [benchmarks/README.md](../benchmarks/README.md)); the command in that file reruns the eval. After a change that moves a score, edit that eval's file (`score`, `size`, `date`, `caveats`) and run `python tools/scoreboard.py` to regenerate the table; `python tools/scoreboard.py --check` fails if it is stale. A new eval adds a new results file in the same PR. On a merge conflict in the table, keep either side and rerun the script.
